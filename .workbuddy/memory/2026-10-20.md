## 账号切换连锁 bug 三连修（用户截图反馈：变色不重置/数据丢失/白屏）

### 根因与修法（5 个文件）
1. **碳情绪颜色不重置回初始色**（`EcoMoodState.ets` + `AccountStore.ets`）：
   `setSession` 切完 LocalStore 命名空间后只 `bump()`（ecoTick+1），而彼时闸门未翻转、业务页面全未挂载 → 广播无订阅者被吞；页面挂载后 `load()` 只拉业务数据，无人 `refresh()` → `AppStorage('ecoLevel')` 停留旧账号档位。另 `ecoOverride` 是全局调试强制档位，不随账号重置。
   修法：`EcoMoodState` 新增 `reset()`（清 override + 档位回 'none' + today 归零，注销用）与 `resetForAccount()`（清 override + refresh，登录用）；`setSession` 在 switchUser 后调 resetForAccount，`logout` 调 reset。
2. **切换账号再登录没有之前记录的数据**（`LocalStore.ets`）：
   预览器无 Preferences（getPreferences 抛错），`switchUser` 清空 records_ 后无盘可读 → 会话内数据蒸发。修法：新增 `userSnap_`/`artSnap_` 会话内账号快照，切走前快照内存态、切回时优先恢复（快照比磁盘新，含落盘失败补救）并补 flush；无快照才走 init 磁盘/种子/零起步口径。
3. **切换账号后再次进入白屏**（`Index.ets` + `ProfilePage.ets`）：
   ProfilePage 在自己还压栈于 `AppRouter.pathStack` 时就 `pathStack.clear()`，紧随的 logout 经闸门把整棵 Navigation 卸载 → 弹栈/销毁被打断，NavPathStack 内部态半死；重新登录后新 Navigation 复用同一栈实例渲染不出来。修法：switchAccount 去掉 clear（只注销，旧会话整棵树随闸门翻转自然销毁）；Index 给 sessionUser 加 `@Watch('onSessionUser')`，登录侧复位 currentTab/位移/胶囊态/底部栏插槽标记 + 清路由栈记录（彼时无 Navigation 挂栈，纯数据操作）+ refresh 碳情绪；注销侧 reset。
- **验证**：BUILD SUCCESSFUL（08:58:01，27s），HAP 晚于全部 5 个改动源码；`.preview` 缓存被 IDE watcher 08:56:36 自动重编（晚于最后源码 08:56:34），本轮无死缓存。
- **预览器遗留边界（已告知用户）**：Preferences 全程不可用 → 预览器刷新/重启仍会丢数据（真机磁盘持久化不受影响）；预览器内切换账号的数据保持靠本次的内存快照。

## 趋势图周视图数据错误修复（用户反馈："我只上传了一天的数据，为什么前几周会有数据"）

### 根因 1：周桶用了累积区间而非周窗口
`MockStore.trendFrom` 周分支原判定：
```ts
if (diff >= 0 && diff < end + 7)   // 累积：今天往前 56 天内的所有记录
```
`end = w*7`（w=7..0），所以今天的记录同时落进全部 8 个桶 → 每根柱都是 23.4。
修复：`if (diff >= end && diff < end + 7)`，即该周自身的 7 天窗口 `[end, end+7)`。
- 参考实现：同文件 `MockStore.trend`（mock 版，line ~387）用 `dateOffset(end + d)` 逐日枚举，天然不重叠。
- day 分支（`dateStr === ds`）与 month 分支（年月前缀匹配）本来就正确。
- Python 模拟验证：单日 23.4kg → 仅「本周」= 23.4，其余 7 根 = 0；多天数据总计守恒（25 = 25）。

### 根因 2：统计区与图表口径漂移（ArkUI 局部更新）
截图里图表是 8 根柱（周口径），但统计区显示「平均 3.34 = 23.4÷7 / 峰值周期 今天 / 积分 234」（日口径）。
同一个 `this.points` 不可能既是 8 桶又是 7 桶 → 原实现是「数组存 @State + `maxKg()/totalKg()` 等方法现场聚合」，
ArkUI 只重求值自身读取了被观测属性的表达式，`ForEach` 按 key 重建了子节点而外部统计表达式未同步。
修复：在 `load()` 中新增 `syncStats()`，与 `points` **同一帧**把聚合结果落成 5 个 `@State` 标量
（`maxV/avgV/totalV/ptsV/maxLb`），`maxKg()/avgKg()/totalKg()/totalPoints()/maxLabel()` 改为读快照。
`points` 的两个赋值分支（成功 / catch）都已调用 `syncStats()`。

### 未改动
`DashboardPage.ets` / `MonthBillPage.ets` 的 `trendMax()` 等是同类「数组 + 方法聚合」模式，
但只用 `day` 粒度、无粒度切换，不存在口径漂移，暂不改。

### 修 2：弹窗「取消后再开卡死」= 定时器竞态（pages/points/PointsMallPage.ets）
- 根因：`openExchange` 与 `closeExchange` **共用一个 exchangeTimer**，且都先 `clearExchangeTimer()` → 入场 16ms 与退场 200ms 互相清除：
  - 退场定时器被入场清掉 → 弹窗永久留场，遮罩继续吃点击（= 卡住）；

- 修法：拆 `exchangeEnterTimer` / `exchangeExitTimer` 两字段 + `clearExchangeTimers()`；`openExchange` 先 `exchangeIn=false` 复位，保证「关→开」能重播入场动画。

### 修 3：弹窗开合无动画 = 参数不是 @Prop（ui/GlassDialog.ets）
- 根因：ArkUI 单向数据流只对 `@Prop/@Link/@ObjectLink` 生效，**子组件的普通成员变量不跟随父级更新**。弹窗的 `visible`/`benefit`/`coupon` 原为普通成员 → 父级改 `exchangeIn`/`detailIn` 时子组件收不到新值 → 入场/退场动画都不播，且退场窗口内换券面板停在旧内容上。

### 修 5：深色模式返回符变黑（ui/Components.ets + pages/article/ArticleDetailPage.ets）

## 指令 D：注册后资料页比主页面慢 → 手快能点到子页面

### 用户原话
「在注册成功后，，有时候信息录入页面会比主页面弹出的慢，，，，，，会导致如果手快能立即点到子页面」

### 根因（三处缺陷叠加）
1. **首帧竞态（核心）**：`Index.profileGate = true` 原写在 `Navigation.onAppear` 里 —— 而 `onAppear` 在**主框架首帧渲染之后**才触发。四个 TabContent（Dashboard/Record/Article/Mine）构造开销大，首帧成本高 → onAppear 迟到 → 主框架「已可见可点」而闸门「还没关」。用户注册完手指悬屏，一戳就误触。
2. **意图标记晚于会话变更**：`LoginGate.submit()` 里 `AppStorage.setOrCreate('pendingProfileSetup', true)` 写在 `await AccountStore.register(...)` **之后**；而 `register()` 内部最后一步 `setSession()` → `AppStorage.setOrCreate('sessionUser')` 已同步触发 `Index.onSessionUser`（@Watch，早于重建）→ onSessionUser 时刻读到的还是 false。
3. **解封信号口径错**：`ProfilePage.aboutToAppear` 发 `profileSetupShown` —— 那是「页面被创建」，不是「已完全上屏」；800ms 兜底定时器与真实上屏时刻完全脱钩。

### 修复（三处协同）
1. **`pages/auth/LoginGate.ets`** — 意图标记**前置到 await 之前**：
   - 新增 `profileSetupIntent`（只给 `Index.onSessionUser` 读，触发闸门预置）
   - `pendingProfileSetup` 同样前置（给 `Navigation.onAppear` 读，触发强制 push）
   - 注册失败（重名/校验不过）**两个标记都撤销**，否则下次登录被误判成注册流程
   - 成功路径**不**清 `profileSetupIntent` —— 交给 Index 消费（若这里抢先清掉而 @Watch 晚一拍触发，就丢了闸门预置的机会）
2. **`pages/Index.ets`** — 闸门机制重构：
   - `profileGate` 由 `@State` 改**普通字段 + `@State profileGateTick`** 触发器。原因：闸门必须在主框架挂载**那一帧**就生效，`@State` 赋值要等下一次 build 才落到属性上（理论晚一帧 ≈16ms），普通字段在 build() 里读到的一定是最新值 —— 零帧延迟。
   - `onSessionUser()`（@Watch，早于重建）读到 `profileSetupIntent` → **预置** `setProfileGate(true)` + 4s 兜底解封定时器（信号丢失防永久锁死）
   - `Navigation.onAppear` 保留 `setProfileGate(true)` 兜底（标记到达时序异常时至少 push 前是关的）
   - `onProfileSetupShown()` 改为**延迟 420ms 解锁**（避开 push 滑入动画期间主框架仍可见的那一段）
   - `Tabs` 与底部栏 Row 的 `.enabled(!this.profileGate)` 各加 **`.opacity(this.profileGateTick >= 0 ? 1 : 0)` 恒读钩子** —— ArkUI 局部更新只刷新依赖了响应式变量的节点，普通字段必须挂 @State 钩子才能让 `.enabled` 更新落地
   - `aboutToDisappear` 补清 `profileUnlockTimer`
3. **`pages/mine/ProfilePage.ets`** — 上屏信号改为真实上屏：
   - `aboutToAppear` 不再发 `profileSetupShown`（那是「页面被创建」）
   - 新增 `NavDestination.onShown`（API 10+，`Callback<VisibilityChangeReason>`，系统级「页面已显示」回调，转场结束才触发）→ `notifyShown()`
   - 根节点 `.onAppear` + 300ms 延时兜底（万一 onShown 在某些设备/预览器不回调）
   - 新增 `shownTimer` 字段，`aboutToDisappear` 清理

### 新增范式
- **普通字段 + @State tick 触发器**：需要「零帧延迟生效」的状态（如首帧闸门）时用这个口径 —— 普通字段存真值（build() 读到即最新），@State tick 只负责触发重渲染，且要用 `.opacity(tick >= 0 ? 1 : 0)` 恒读钩子挂到每个消费点。
- **`onShown` 是 NavDestination 的真实上屏回调**（`ets/component/nav_destination.d.ts:860`，API 10+；API 21+ 签名改为带 `VisibilityChangeReason`）。比 `aboutToAppear` 准得多，适合「转场完成才做事」的场景。
