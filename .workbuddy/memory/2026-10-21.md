## 指令 F：二级页面入场动画缺失（「只有阴影没动画ui弹出」）

### 用户原话
「页面都具有bug只有阴影没动画ui弹出」（截图：积分商城）

### 修复（26 个页面统一）

### 关键实现细节（踩坑）
1. **属性必须写在容器闭合 `}` 之后**，不能写在闭合前 —— 闭合前的位置属于「最后一个子节点的属性链」，Builder 形式页面（`Column() { this.DetailContent() }`）会直接变成 Builder 调用的属性而编译失败。
2. **属性链扫描只能取「闭合行往前的连续属性行」**。第一版扫了整个容器区间，把内层 Scroll 内容列的 themeTick 钩子 opacity 也误打补丁（无害但冗余，已还原）。
3. **onDisAppear 是大写 A**（`onDisAppear`），写成 `onDisappear` 编译报 "Property does not exist on type"。
4. **字段必须插进「包含 NavDestination 的那个类」**。PointsRecordPage 有内嵌 @Component（LogRow），脚本用「第一个 build()」定位，把字段插进了内嵌组件 → 外层组件报 Property 'pageIn' does not exist。**可靠检测：字段行与 NavDestination 行之间不允许出现顶层 `^}`**。
5. 上一轮 620ms 批量脚本遗留了 23 个文件的错误路径 import（`from 'ui/AppleMotion'`，缺 `./`/`../`），与本轮正确 import 重复 → Duplicate identifier。已全局清理（保留正确路径、丢重复行）。
6. **没用 `.transition()`**：无条件渲染的组件首次挂载时 transition 不保证播放（项目里所有 transition 用例都挂在条件渲染分支上）。onAppear + 状态驱动是已验证可靠的手法。

## 指令 G：弹窗「取消后再点开」入场动画丢失（用户复现反馈）

### 用户原话
「取消后，在点还是会触发这个bug」（承接「只有阴影没动画ui弹出」）

### 根因（本轮真正元凶，上一轮我改错了地方）
`.animation()` **必须是静态值**。上一轮（指令 E）我把弹窗动画写成了三元：
```ts
.animation(this.visible ? { curve: spring() } : { duration: 200, curve: OUT })
```
`animation` 表达式与 `opacity`/`scale` 在同一帧求值，三元写法让「animation 的更新」与「属性变化」互相竞争 —— **取消后再点开弹窗时入场动画丢失**，面板直接以终态出现（= 用户看到的「只有阴影没动画」）。原代码用静态常量 `{duration:200, curve:EaseOut}` 反而一定播。

### 修复
1. **`ui/GlassDialog.ets`（两个弹窗）**：三元 animation → **静态** `.animation({ curve: AppleMotion.spring() })`。静态值在组件创建时即设定，之后任何属性变化都稳定用它；弹簧给入场 Q 弹感，退场同一条弹簧反向。
2. **`pages/` 26 个页面**：入场动画从「给最外层容器挂 `.animation()`」改为 **`getUIContext().animateTo()` 驱动**。原因：`.animation()` 会按作用域**继承给所有子组件**（含条件渲染的弹窗/覆盖层），父子动画叠加时 ArkUI 行为不稳定，可能压制弹窗动画。animateTo 只动画化闭包内状态变更影响的属性，作用域显式、零继承歧义。

### 新增范式（重要）
- **`.animation()` 禁止写依赖状态的三元/表达式，必须静态常量**。要区分入退场方向时用 `.transition(asymmetric(in, out))`（插入/删除触发）或 animateTo。
- **父容器的 `.animation()` 会污染子组件**（尤其弹窗/覆盖层）。页面级入场动画优先用 `animateTo`，不要给含弹窗的容器挂 `.animation()`。

### 验证
- assembleHap **BUILD SUCCESSFUL**；三元 animation 实际代码清零（仅剩注释说明）
- 26 个页面全部改 animateTo 驱动；HAP 09:20:51 晚于全部源码改动
