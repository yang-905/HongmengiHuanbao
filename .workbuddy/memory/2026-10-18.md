## 经验：ArkUI 布局类 bug 的排查要点
- `offset()` 只改变**绘制位置**，不改变**布局占位** —— 想让子节点脱离布局流，
  必须换容器（Stack 叠加 / position），不能靠 offset。
- 定宽 `Text` + `layoutWeight` 父级：宽度约束要跟到父槽位，写死宽度在

# 追加：CfButton flex 按钮溢出屏幕

## 现象
徽章详情半模态（`BadgeDetailSheet`）底部「分享成就」按钮**整体溢出容器右边缘**，
屏幕里只剩按钮左半截，「↗ 分享成就」文字被切在中间。

## 根因（组件层，非页面层）
`ui/Components.ets` 的 `CfButton` 里，`flex: true` 实现为
`.width('100%')`。ArkUI 的 `'100%'` 参照的是**父容器宽度**，
所以「关闭」(96 最小宽) + 「分享成就」(= 父 Row 宽度) + space(12)
合计远超父容器，主按钮被整体挤到屏幕外。

## 修复
`CfButton` 拆成两条互斥渲染路径：
- `flex: true` → 委派 `CfButtonFlexBody`（新增私有 struct），内部调 `layoutWeight(1)`；
- `flex: false` → 原 `ButtonBody`，用 `width('100%')`（block 语义正确）或不设宽。

拆两个 struct 而非条件表达式，是为了**非 flex 路径完全不调用 layoutWeight**，
规避 ArkUI 下 `layoutWeight(0)` 仍参与分配的坑（同 `Index.ets` 注释）。

## 连带修复（同源缺陷，本次一并生效）
`flex: true` 共 3 处调用，全部是「次要按钮 + 主按钮」并排，此前都溢出：
- `pages/points/BadgeDetailSheet.ets:387,394` — 分享成就 / 去赚积分
- `pages/article/QuizSheet.ets:371,378` — 完成 / 提交答案

# 追加四：弹出面板（bindSheet）改液态玻璃底

## 现象
半模态面板（徽章详情等）观感像"一张白纸贴在屏幕上"，没有苹果液态玻璃的悬浮感。

## 根因
面板根容器用了 `Neutral.BG` = `#FBF8F3` —— **完全不透明的纯色**。
即使加了模糊，也被这层实色整个盖住，底下页面内容一点都透不出来。

## 修复
### 1. Theme.ets 新增面板玻璃材质
```ts
static readonly SHEET_BG: string = 'rgba(255,255,255,0.42)';
static readonly SHEET_BLUR: number = 30;
```
透明度 0.42 比底部胶囊(0.62)更透：面板面积大且内部还有子卡片，
底色太实会与内部卡片白色边界打架；0.42 既透得出背景又够文字对比度。
模糊 30 > 胶囊的 20：面板遮住的内容更多，需更强虚化压住底下文字，
避免与面板自身文字产生"双层文字"噪声。

### 2. 三个面板根容器统一改造
- `BadgeDetailSheet.ets`：`Neutral.BG` → `Glass.SHEET_BG` + `backdropBlur(SHEET_BLUR)`
- `BehaviorAddSheet.ets`：同上
- `QuizSheet.ets`：原本**完全没设根背景**（靠系统默认底），补上玻璃底

三者均加顶缘 `.border({width:{top:1}, color: Glass.HIGHLIGHT})` 做玻璃上沿受光面。

### 关键：必须用 backdropBlur 而非 backgroundBlurStyle
`backgroundBlurStyle` 只模糊系统壁纸/窗口背景，对组件下方**实时内容**不生效，
看起来就是一层贴纸；`backdropBlur(radius)` 真正实时采样组件后方像素，
滚动时毛玻璃跟着变，才是"活"的玻璃（同 `Index.ets` OrbButton 的做法）。

## 沉淀：做毛玻璃前先确认底色不是不透明实色
项目里 `Glass.CARD_BG`(0.86) / `BOTTOM_BAR_BG`(0.62) 都是半透明，玻璃能透；
但普通页面容器习惯用 `Neutral.BG`（纯色）——**任何要加 backdropBlur 的容器，
底色必须先改成半透明**，否则模糊白加。

验证：hvigor BUILD SUCCESSFUL。

# 追加六：CfCloseBtn 叉号交叉点裂开（重影复发）

## 现象
`CfCloseBtn` 矢量叉号仍显示"双线/重影"，两条斜线没有精确交于一点。

## 排查方法：手工 PNG 解码 + 逐像素 ASCII 扫描
无 PIL 且 pip 不可用（代理 502），改为用 Python `zlib`+`struct` 手工解码 PNG
（IHDR/IDAT 解析 + 5 种 filter 类型反滤波），再按亮度阈值把笔画打成
`#`/`+`/`.` 字符网格，直接看笔画走向。

扫描结果（叉号区域）：
```
189 ....... +#+## .###.....
190 .........+#+#####......
```
笔画中间出现 `+#+` 分叉 → 证实两条线**未精确交叉**，各自有亚像素级偏移。

## 根因
```ts
Row().width(len).height(1.6)   // ← 1.6 是小数
```
ArkUI 布局时把 1.6px **向上取整到 2px**，两条线的中心各自偏离 Stack 中线；
再旋转 ±45°，偏移方向相反 → 交叉点裂开。

## 修复
- `height(1.6)` → `height(2)`（**必须整数**），两条线共用同一中线
- 去掉 `borderRadius(1)`：2px 线上的圆头会加剧视觉断裂
- 长度提取 `armLen()` 用 `Math.round` 保证整数

## 沉淀：ArkUI 里画细线/图形时避免小数尺寸
`.height()`/`.width()` 传小数会被布局取整，多个子组件（如旋转的两条线）
各自取整方向不同时会产生错位。若必须用小数（如 1.6vp 发丝线），
改用 `.borderWidth()` 或单条路径绘制，不要靠多组件旋转交叉。

验证：hvigor BUILD SUCCESSFUL。

# 追加七：分段控件药丸右缘绿白光晕

## 现象
日/周/月 选中「月」（最右一档）时，药丸右缘有一圈绿白色晕溢出到页面背景。

## 排查：像素扫描量化
沿 y=60 横向扫描判定绿色像素，药丸主体绿色止于 x=233，
但 x=234~241 仍有一串绿白色调残留：
```
233 ( 94,176,154) ← 药丸主体绿
234 (131,185,171) ┐
235 (206,243,235) │ 投影残留（绿调渐淡）
...
241 (229,233,222) ┘
242 (245,244,232) ← 才回到纯背景
```
即投影向右溢出约 8px。

## 根因（两层）
1. **投影过大**：`Shadow.brand()` = `0 6px 18px rgba(63,191,159,0.28)`，
   带 6px 偏移 + 18px 半径的品牌绿投影。最右一档紧贴轨道边缘，投影必然溢出。
2. **clip 加错了层级**：轨道与药丸是 **Stack 里的兄弟节点**，
   `clip(true)` 加在轨道 Row 上**裁不到药丸**。必须加在 Stack（共同父级）上。

## 修复
- 投影改为紧致版：`{radius:4, color:'rgba(63,191,159,0.30)', offsetX:0, offsetY:1}`
  （无大偏移、小半径，范围落在药丸自身附近）
- `.clip(true)` 从轨道 Row 移到 **Stack**（轨道+药丸的共同父级）

## 沉淀：clip 要加在「被裁内容的所有祖先链上」
Stack 里多个兄弟图层时，某节点自己的 clip **不影响兄弟节点**的投影/模糊溢出。
要裁住所有兄弟，必须加在它们的**共同父容器**上。
本项目同类结构还有 `Index.ets` 的 SlidingPill（底部药丸）——
它投影大但四周留白充足，故未溢出，暂未改动。

验证：hvigor BUILD SUCCESSFUL。

# 追加八：动态碳主题推广到全应用（27 个页面）

## 需求
一级/二级/三级页面背景全部随当日碳排放动态变化。

## 架构：全局单例 + AppStorage 响应式
新增 `data/EcoMoodState.ets`（判定）与 `data/EcoMoodRuntime.ets`（信号中转）。

```
LocalStore.addRecord/removeRecord
   └─▶ EcoMoodRuntime.bump()          // 自增 AppStorage['ecoTick']
          └─▶ 页面 @StorageLink('ecoTick') onStorageChange()
                 └─▶ EcoMoodState.refresh() → 写 AppStorage['ecoLevel']
                        └─▶ 27 页 @StorageProp('ecoLevel') 背景过渡
```

**为什么不各页面自己判档**：27 处重复读存储，且档位可能短暂不一致
（用户会看到「上一页绿、下一页黄」）。全局单例保证全应用同帧一致。

## 重大踩坑：ArkTS 禁止函数类型作为字段/参数
最初用「注入刷新回调」打断 LocalStore ↔ EcoMoodState 循环引用：
```ts

static bind(f: (x: void): void): void {}              // ❌ 连 (x:void):void 也不行
```
报错：`Unexpected token` / `arkts-no-untyped-obj-literals`，
且会**级联**产生几十条看似无关的误报（行号全在我没碰过的原有代码上）。

→ 最终方案：LocalStore 只调 `EcoMoodRuntime.bump()` 发自增信号，
**不认识任何函数**，编译期依赖单向不成环。
这印证了本项目「禁止回调注入」的实现风格。

## 批量改造（27 文件 / 28 处背景）
脚本化注入，每个页面统一加：
```ts
@StorageProp('ecoLevel') ecoLevel: string = 'none'
@StorageLink('ecoTick') ecoTick: number = 0
private ecoBg(): string { return EcoTheme.bg(this.ecoLevel) }
onStorageChange(key: string): void {
  if (key === 'ecoTick') { EcoMoodState.refresh() }
}
```
背景改为 `.backgroundColor(this.ecoBg()).animation({duration:620, curve:Curve.EaseInOut})`。

**批量脚本的坑**：注入 import 时正则漏了逗号（`Space\n  EcoTheme,`），
27 个文件全语法错误；相对路径按目录深度算，
`pages/OnboardingPage.ets` 在 pages 根目录（只需 `../data/`）被算成 `../../data/`。
→ 批量改 ArkTS 后**必须逐类抽查 + 编译验证**，不能只看脚本输出。

## 顺带修复（并行任务遗留）
`SuperTerminalPage.sync()` 被改成 `async`，但调用处仍写 `.onClick((): void => this.sync())`，
`Promise<void>` 不能赋给 `void`。改为不标注返回类型后通过。

# 追加九：DeviceKit.ets 279 条编译错误（级联误报排查范式）

## 现象
`distributed/DeviceKit.ets`（并行任务新增的超级终端组网层）报 **279 条错误**，
报错信息极其诡异：
- `Cannot find name 'isReady' / 'ctx' / 'granted' / 'list' …`
- `'boolean' only refers to a type, but is being used as a value here`
- `Cannot find name 'async'`、`'=>' expected`、`Unexpected token`
- `'DeviceKit.dm' is possibly 'undefined'`（而 dm 是静态字段）

## 关键判断：这些全是级联误报
真正的错误只有一处 —— **第 38 行**：
```ts
private static onChange_: ((x: void): void) | undefined = undefined   // ❌
```
**ArkTS 严格模式禁止把函数类型用作字段/参数类型。**
这一行让解析器从该处起全线崩溃，其后所有 token 都被错误解析，
于是报出「找不到明明就在上面的名字」「把 boolean 类型当值用」这类假象。
错误行号横跨 38~247，覆盖整个文件。

## 修复
改为 AppStorage 自增序号做信号（同本项目 `EcoMoodRuntime` 套路）：
```ts
private static changeTick_: number = 0
static readonly KEY_TICK: string = 'deviceTick'
static fire(): void {
  DeviceKit.changeTick_++
  AppStorage.set<number>(DeviceKit.KEY_TICK, DeviceKit.changeTick_)
}
```
同步删除 `setOnChange()` 及其在 `SyncEngine.boot()` 里的注册调用
（调用点改为由页面用 `@StorageLink('deviceTick')` 自行响应）。

结果：**279 条 → 0 条，BUILD SUCCESSFUL**。

## 沉淀：ArkTS 编译错误排查范式（重要）
1. **报错信息出现「找不到明明存在的名字」「类型被当值用」→ 优先怀疑解析器已崩溃**，
   往上翻找第一条**语法类**错误（Unexpected token / '=>' expected / ':' expected），
   那才是根因；后面的都是级联产物。
2. **ArkTS 硬性限制：禁止把函数类型用作字段或参数类型**。
   `private f: (x: void): void` 与 `set(cb: (x: void): void)` 都编译失败，
   写完整签名也不行。
   需要「通知多方」时用 AppStorage 自增序号 + `@StorageLink`，
   需要「单点回调」时由调用方在 `onStorageChange` 里统一分发。
3. 本项目因此已有两处同类约定：`EcoMoodRuntime.bump()` 与 `DeviceKit.fire()`。

验证：hvigor BUILD SUCCESSFUL。

- 右侧从「标签 | Blank | 数值」横排，改为**竖排指标格** `MetricCell`：
  标签在上、数值在下，`layoutWeight(1)` 均分，数值右对齐 + 省略号

`certNo` 与「消耗/颁发于」两行均补 `maxLines(1)` + 省略号 +

这些位置都是纯数字，风险低，但系统字体放大时会撑破卡片。

Row 内多个 Text 想要"该省略就省略"，必须**同时**具备：
1. `layoutWeight(1)` —— 参与剩余空间分配
2. `constraintSize({ minWidth: 0 })` —— 允许被压缩到 0
3. `maxLines(1)` + `textOverflow(Ellipsis)` —— 压缩后显示省略号而非换行

# 追加十六：开屏页「一触青绿」消失

`showSplash` 刚从 `true` 设好就被立刻置回 `false` —— 开屏页一闪而过，
实际等于没有。

原注释说这是「兜底关闭启动页 —— Previewer 里 setTimeout 可能不触发」，
但代价是把启动页整个废掉了。**兜底不该写在会必然触发的生命周期里**。

## 修复
### 1. onPageShow 只做路由栈同步，不再碰 showSplash
启动页关闭只走两条正路（都在 aboutToAppear 挂载，与 onPageShow 无关）：
- 定时器（1.6s）
- 用户点击（SplashPage 自带 onClick）

### 2. 补齐真正的淡入淡出
原代码注释写「淡出」但只是 `showSplash = false` 硬切，观感像闪屏。
- `SplashPage` 新增 `@State alpha`，`aboutToAppear` 里 420ms 淡入
- `Index` 新增 `splashContentOpacity`(0→1) + `splashContentScale`(0.98→1)，
  让**底层内容在启动页淡出时同步浮现**，两者交叉过渡
- 统一 `fadeOutSplash()`：定时器与点击跳过都走它，观感一致
- 停留 1400ms → **1600ms**（原值偏仓促，「一触青绿」刚出现就没了）
- `splashTimer` 纳入 `aboutToDisappear` 清理，避免泄漏

现在 `showSplash` 全项目只剩 1 个写入点（fadeOutSplash 内），不会再被误触。

## 沉淀（重要）
**`onPageShow` 在 ArkUI 里首次创建时就会触发**，
不能当作「用户返回」的钩子用。要感知返回，得配合
路由栈状态比对（如本项目的 `syncStackState`：`pathStack.size() > 0`）。
凡是在 onPageShow 里做「一次性初始化/关闭」的动作，都可能被首次触发打乱。
