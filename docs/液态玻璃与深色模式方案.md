# 一触青绿 · 液态玻璃与深色模式方案

> 适用版本：OpenHarmony API 24 / ArkTS 声明式 UI（`app/entry`）
> 归口文件：`ui/GlassLight.ets`（光照与材质唯一真源）、`ui/GlassSurface.ets`（玻璃组件）、
> `ui/Theme.ets`（色值令牌）、`data/ThemeMode.ets`（主题切换与持久化）
> 本文是**实现说明书**：新增任何玻璃面 / 任何色值前先读第 4 章。

---

## 0. 一句话结论

全应用的玻璃材质由**一个 135° 左上光源 + 两张独立参数表（浅色 / 深色）**驱动：
页面只声明「材质档位（pill/card/panel）+ 环境底色」，所有高光、内阴影、边缘、投影
都由 `GlassLight` 算出并**预合成进同一条渐变**；深色模式走 `ThemePalette.applyDark()`
整体换血色值令牌，再用 `themeTick` 广播触发全应用重建；数据写入后由 `ecoTick` +
`@Watch` 驱动各页自动重拉，无需手动刷新。

---

## 1. 设计目标与原则

| # | 原则 | 具体要求 |
|---|---|---|
| 1 | **单一光源** | 全库只有一个主光源：左上 45°（渐变角 135°）。任何玻璃面的受光边必须在**顶 / 左**，背光边在**底 / 右**；禁止页面自己画反方向高光 |
| 2 | **单一真源** | 光照参数只在 `GlassLight` 里定义，色值只在 `Theme` 的四张表里定义。页面里**不允许**出现光照数值或色值字面量 |
| 3 | **可读性优先** | 文字永远压在光照层之上；玻璃在任何背景下都要保证正文对比度 ≥ 4.5:1（深色实测见 3.4） |
| 4 | **性能红线** | card 档永不挂 `backdropBlur`；一屏内同区域不叠加多层模糊；玻璃面一律「零子层」单层合成 |
| 5 | **深浅自洽** | 深色是**应用内开关**（设置页）+ 持久化，不跟随系统；系统栏图标色显式下发，不依赖系统猜测 |
| 6 | **数据即时** | 任何数据写入后，用户**不需要手动刷新**：列表、统计、配色一起自动更新（见第 7 章） |

## 2. 液态玻璃：光照模型

### 2.1 光源定义（全库唯一）

```
LIGHT_ANGLE = 135°        // ArkUI linearGradient 角：左上(colors[0]) → 右下(colors[last])
顶边受光 → 180°（顶→底）
左边受光 →  90°（左→右）
外投影方向 = 右下（浅色模式下 alpha ≤ 1.2%，见 2.5）
```

### 2.2 五层光照栈（物理近似，不做光线追踪）

| 层 | 名称 | 作用 | 实现 |
|---|---|---|---|
| ① | 接触纱 scrim | 亮背景下把玻璃"钉"在背景上，托住文字对比度 | 135° 定向暗纱，**只在右下压深**（平铺暗纱会把玻璃蒙灰） |
| ② | 对角光染 wash | 模拟曲面受光：左上亮 → 中性 → 右下内阴影 | 多段停靠点，高光**只集中在左上角 0~38%**，中段归零 |
| ③ | 顶边菲涅尔 | 边缘反射（顶沿更亮） | 180° 亮→透明，带宽 13%（深色 9%） |
| ④ | 左边菲涅尔 | 同上（左沿） | 90° 亮→透明 |
| ⑤ | 文字暗纱（仅深色） | 顶浅底深，防止文字浮在玻璃上发飘 | 180°，alpha 0.02→0.08 |

外加：**1px 四边异色描边**（上/左 = 受光白，下/右 = 背光深）+ **右下外投影**。

### 2.3 两条硬约束（本项目踩过的两个大坑）

**约束 A：零子层。**
光照层不能写成 `Stack { 100%×100% 的渐变层; 内容 }`。在 fit-content / 高度自适应的
容器里，百分比按**祖先约束最大值**解析，会把元素撑成整屏巨块（实测：药丸被撑成
约 210×586vp）。因此所有玻璃面一律把光照**压进元素自身的 `linearGradient`**。

**约束 B：先 α 合成，再进渐变。**
ArkUI 的 `linearGradient` **不预乘**，两个 rgba 停靠点之间逐通道（含 alpha）插值。所以：

```
❌ 错误：把"半透明深墨"和"白底"直接相邻当停靠点
   0.90 rgba(10,16,14,0.018)  →  1.00 rgba(255,255,255,0.72)
   中段插出 rgba(≈132,135,134,0.37) 的半透明灰 = 卡片右下角一块脏暗角
   且中段 alpha=0 会把卡片底色挖空（卡片看起来不存在）

✅ 正确：先把光照 over 到底色上，再作停靠点（GlassLight.over）
   每个停靠点自带完整底色 → 任意两点插值只在"同一块玻璃的亮部/暗部"之间过渡
```

`GlassLight.surface(base, tier, ambient, gloss)` = 该约束的唯一实现入口，
内部流程：`rgbaOf(base)` → 逐档算出 wash 停靠点 → `over(base, wash_i)` → 输出渐变。

### 2.4 材质三档与参数表

按**面积反向取值**：同样 alpha 铺在小面积上视觉浓度更高，所以
`pill < card < panel`。所有 alpha 都乘环境自适应系数 `f`。

**环境自适应**

| 模式 | 背景亮度 l（Rec.709） | 系数 |
|---|---|---|
| 浅色 `adapt(l)` | l > 0.78（亮底） | ×0.92（防过曝） |
| | l < 0.40（暗底） | ×1.22（防发灰） |
| 深色 `darkAdapt(l)` | l < 0.12（近黑） | ×1.18（边缘提亮防消失） |
| | l < 0.25（深底） | ×1.08 |

**浅色参数表**

| 参数 | pill | card | panel | 说明 |
|---|---|---|---|---|
| `tintAlpha` 染色层 | 0.42·f | 0.72+(f−1)·0.1 | 0.50·f | 夹在 [0.26, 0.92]；card 是"白玻璃卡"可读性底线 |
| `washAlpha` 对角光染 | 0.10·f | 0.11·f | 0.13·f | 只做左上入射感 |
| `edgeAlpha` 菲涅尔 | 0.26·f | 0.30·f | 0.34·f | 边缘亮带 |
| `innerAlpha` 内阴影 | 0.02·f | 0.02·f | 0.03·f | 仅背光侧收边，**不做体积** |
| `edgeBorderAlpha` 受光描边 | 0.40·f | 0.46·f | 0.52·f | 上/左 1px |
| `shadeBorderAlpha` 背光描边 | 0.025 | 0.02 | 0.03 | 下/右 1px；背景 l<0.40 时再 ×0.6 |

**深色参数表（独立参数，不是浅色反转）**

| 参数 | pill | card | panel | 说明 |
|---|---|---|---|---|
| `tintColor` 白微染 | 0.13 | 0.09 | 0.11 | **白色微染**（236,244,246），不是深色染色；近黑底 +0.02、彩色底 −0.02，夹 [0.05, 0.20] |
| `washAlphaDark` | 0.04·d | 0.05·d | 0.05·d | 提亮集中到左上角 |
| `edgeAlphaDark` | 0.60·d | 0.52·d | 0.56·d | **上限 0.62**（再高烧出死白亮线） |
| `innerAlphaDark` | 0.05·d | 0.04·d | 0.045·d | 与浅色同量级，压暗即脏 |
| `edgeBorderAlphaDark` | 0.62·d | 0.55·d | 0.50·d | 冷白 236,244,246；上限 0.80 |
| `shadeBorderAlphaDark` | 0.07 | 0.06 | 0.065 | 深青黑 8,14,16，只做 1px 收边 |

**wash 停靠点**（进入 `over()` 之前的光照层定义）

| 模式 | 停靠点 |
|---|---|
| 浅色 | 0 / 0.12（峰值）/ 0.38 / 0.55（归零）/ 0.90 / 1 |
| 深色 | 0 / 0.14 / 0.34 / 0.52 / 0.86 / 1 |

### 2.5 描边与投影

- **描边**：`GlassLight.borderColors(tier, ambient, gloss)` 返回 `EdgeColors`
  （top/left 亮、right/bottom 深）。**宽度只能写整数 1vp**——非整数（1.5vp）配合
  `borderRadius` 会在描边内侧留下一条未填充的暗缝，横贯卡顶边，看起来就是"暗角"。
- **投影** `GlassLight.shadowOf(tier)`：

| 档位 | 浅色 | 深色 |
|---|---|---|
| pill | r8 / `#02000002` / (0,0) | r6 / `#06000000` / (0,1) |
| card | r10 / `#03000003` / (0,0) | r10 / `#08000000` / (0,2) |
| panel | r12 / `#03000004` / (0,0) | r14 / `#0A000010` / (1,3) |

  浅色投影 alpha 必须 ≤ 1.2% 且偏移归零：卡片本体比页面底亮约 10 级，
  任何明显的黑投影都会在四周压出一圈灰晕，反而更像"脏边"。
  层次由「白玻璃 vs 页面底 + 1px 受光描边」建立，不靠投影。

### 2.6 玻璃令牌（`Theme.Glass`，浅/深两套）

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `CARD_BG` | rgba(255,255,255,0.72) | rgba(255,255,255,0.07) | 内容卡片底 |
| `PANEL_LIVE_BG` | 0.50 | 0.06 | 悬浮面板 / sheet |
| `PILL_BG` | 0.42 | 0.11 | 内嵌药丸 |
| `TOPBAR_BG` | 0.50 | 0.06 | 二级页顶栏 |
| `SEGMENT_TRACK_BG` | 0.38 | 0.07 | 分段控件轨道 |
| `DISC_BG` | 0.52 | 0.09 | 玻璃圆盘 |
| `DISC_SOLID_BG` | `#FFFFFF` | `#22322E` | 实底圆盘（logo 盘） |
| `BOTTOM_BAR_BG` | 0.12 | 0.05 | 底部导航胶囊 |
| `EDGE` | rgba(255,255,255,0.52) | rgba(236,244,246,0.14) | 旧均白描边（**新代码请用 borderColors**） |

### 2.7 滚动视差

`GlassLight.nudge(dy)` 由列表 `onScroll` 调用，累加后 80ms 心跳写入
`AppStorage('glassParallax')`、每拍衰减 ×0.78；浅色幅度 ±10vp、系数 0.22；
深色 ±5vp、系数 0.11（暗底同样幅度更"跳"）。纯合成层平移，不触发布局。

## 3. 深色模式

### 3.1 换血链路（为什么需要 themeTick）

ArkTS 的 **static 字段不响应**：`ThemePalette.applyDark()` 改完静态色值后，
已建完的页面不会自动重读。因此：

```
设置页开关
  → ThemeMode.setDark(dark)
      → ThemePalette.applyDark(dark)           // ① 重写全部静态色值令牌
      → ThemeMode.applySystemBar(dark)         // ② 系统栏图标反色（见 3.3）
      → ThemeMode.persistDark(dark)            // ③ 落盘（失败只记日志，不阻塞）
      → ThemeMode.bumpRender()                 // ④ AppStorage('themeTick') +1
          → 每个页面/组件的 @StorageProp('themeTick')
              → build() 重执行 → 重新读取 static 色值 → 新配色上屏
```

约定：**每个页面、每个自绘组件都要订阅 `themeTick`**，并在 `build()` 里以
`.opacity(this.themeTick >= 0 ? 1 : 0)` 恒读一次（恒为 1，只为建立依赖）。
当前 34 个页面全部已订阅。

### 3.2 深色玻璃为什么是"白色微染"

暗背景上玻璃要**比背景亮**才浮得起来，而不是靠深色叠加或阴影压暗：

- 旧方案（深色染色 `rgb(23,36,34)` + 高内阴影 0.153 + 全幅文字暗纱）→
  玻璃面与页面底几乎同色 → 玻璃"消失"，只剩右下角一大块脏暗角。
- 现方案：白色微染 0.07~0.13（叠在 `#111917` 上得约 `(34,42,39)`，比底亮 17 级）
  + 高权重边缘光 + 极轻内阴影（0.04）→ 层次全部由边缘光承担。

### 3.3 系统栏（状态栏 / 导航条）适配 ★ 易漏项

系统只认 `module.json5` 的 `ohos.extension.colorMode = dark` 声明，
**并不知道**用户在设置页把界面切成了深色。不显式下发图标色就会出现
「深色界面 + 深色状态栏图标 = 时间/电量看不见」。

实现：

```
EntryAbility.onWindowStageCreate
  → ThemeMode.attachWindow(mainWindow)     // 背景透明 + 按当前主题下发图标色
       setWindowSystemBarProperties({
         statusBarColor: '#00000000', navigationBarColor: '#00000000',
         statusBarContentColor:     dark ? '#F2F5F3' : '#1A1F1C',
         navigationBarContentColor: dark ? '#F2F5F3' : '#1A1F1C'
       })
ThemeMode.setDark / init → applySystemBar(dark)   // 每次换血重新下发
```

> 为什么不跟随系统深色：本应用是"应用内开关 + 持久化"，若同时跟随系统，
> 「系统深色 + 应用浅色」时页面底色与系统状态栏会互相打架。深浅完全自洽，
> 系统侧只保留能力声明 + 系统栏配色。

### 3.4 深色对比度实测（WCAG）

| 位置 | 前景/背景 | 对比度 | 结论 |
|---|---|---|---|
| 卡片正文 | `#E9F0ED` on (34,42,39) | 5.94:1 | AA ✓ |
| 卡片副文 | `#9DB1AC` on (34,42,39) | 4.30:1 | AA(大字) ✓ |
| 卡片弱文 | `#6B7B75` on (34,42,39) | 2.97:1 | 仅装饰用 ✓ |
| 底部胶囊选中字 | 近黑/近浅 on 胶囊 | 6.94:1 | ✓ |
| 底部胶囊未选字 | `TEXT_MUTED` on 胶囊 | 3.39:1 | 大字 ✓ |
| 科普页选中 chip | 近白玻璃 + 近黑字 | 4.29:1 | ✓ |

### 3.5 深色下的碳情绪（EcoMood）

四档情绪色各有浅/深两套**实底**（页面根底色）与强调色：

| 档位 | 浅色 SOLID | 深色 SOLID | 深色 ACCENT |
|---|---|---|---|
| eco 很好 | `#F2FBF7` | `#122822` | `#71DCC0` |
| good 不错 | `#F4FAF3` | `#142A23` | `#85D8B2` |
| warn 偏高 | `#FDF8EF` | `#2A2114` | `#EAC78D` |

所有页面用 `EcoTheme.bgSolid(level)` 作**不透明**页面根底（半透明根底会落到系统白底，
把玻璃的 backdropBlur 采样成白色，液态感直接消失）。

## 4. 组件与用法规范

### 4.1 组件地图

| 组件 | 文件 | 用途 | 光照 |
|---|---|---|---|
| `CfCard` | `ui/Components.ets` | 内容卡片（默认 `glass=false`） | `surface(CARD_BG, card)` |
| `GlassPanel` | `ui/GlassSurface.ets` | 大面板 / Hero / 空态 | `surface()`，可选 `bgGradient` |
| `GlassPill` | `ui/GlassSurface.ets` | 分类 chip / 收藏钮 | `pillSurface()` |
| `CfGlassDisc` | `ui/Components.ets` | 玻璃圆盘（图标钮） | `surface(DISC_BG, pill)` |
| `CfTopBar` | `ui/Components.ets` | 二级页顶栏 | `surface(TOP_BAR_BG, pill)` |
| `CfButton` | `ui/Components.ets` | 主/次按钮 | 实底 + `shadowOf` |
| `GlassLight.panelSurface(ambient)` | `ui/GlassLight.ets` | **无包装组件的页面级面板**（sheet / 悬浮分组 / 说明条） | `surface(PANEL_LIVE_BG, panel)` |
| `GlassLight.borderColors(tier, ambient, gloss)` | `ui/GlassLight.ets` | 玻璃面的 1px 四边异色描边 | — |

### 4.2 新增一个玻璃面（标准写法）

```ts
// ① 优先用现成组件
CfCard({ pad: Space.MD }) { /* 内容 */ }

// ② 页面级面板（没有包装组件时）
Column() { /* 内容 */ }
  .width('100%')
  .padding(Space.MD)
  .linearGradient(GlassLight.panelSurface(EcoTheme.bg(this.ecoLevel)))  // 光照在这里
  .backdropBlur(GlassLight.blurScaled(Glass.LIVE_BLUR))                 // 必须过 blurScaled
  .border({ width: 1, color: GlassLight.borderColors(GlassTier.PANEL, EcoTheme.bg(this.ecoLevel), 1) })
  .borderRadius(Radius.XL)
  .shadow(GlassLight.shadowOf(GlassTier.PANEL))
  .clip(true)
```

> 页面**不需要**判断深浅色：底色令牌、光照参数、描边、投影都由 `ThemePalette.dark`
> 内部切换。页面唯一要做的是订阅 `themeTick` 并在 `build()` 恒读一次。

### 4.3 Do / Don't

| ❌ Don't | ✅ Do | 原因 |
|---|---|---|
| `.backgroundColor(Glass.PANEL_LIVE_BG)` 平涂 | `.linearGradient(GlassLight.panelSurface(ambient))` | 平涂没有方向性，深色下是没边缘光的灰片 |
| 自己写 `rgba(255,255,255,0.22)` 高光/描边 | `GlassLight.borderColors()/surface()` | 违反单一光源，深浅各写一套必然漏 |
| 渐变色标里「深色 rgba → 白色 rgba」直连 | 先 `GlassLight.over()` 再进渐变 | 逐通道插值会插出半透明灰带（脏暗角） |
| 停靠点里出现 `alpha = 0` 的中间点 | 预合成，底色每个停靠点都自带 | 中段会被挖空，元素"看起来不存在" |
| `.border({ width: { top: 1.5 } })` | 四边等宽整数 `1vp` | 非整数描边 + 圆角会在内侧留暗缝 |
| 卡片刻意加 `.backdropBlur()` | card 档保持 0 模糊 | 一屏十几张卡各一层离屏渲染会掉帧 |
| 页面根底写半透明 `EcoTheme.bg()` | 写不透明 `EcoTheme.bgSolid()` | 半透明根底落到系统白底 → 玻璃采样成白板 |
| 直接写 `#FFFFFF` / `#1A1F1C` 当文字色 | 用 `Neutral.TEXT / TEXT_SUB / TEXT_MUTED` | 深色下白字会看不见（品牌实底上的白字除外） |
| 在页面里读 `Theme.xxx` 静态值当初始值存字段 | 每次 `build()` 里现取，或订阅 `themeTick` | static 换血不会回灌已存在实例的字段 |
| 用 `onStorageChange()` 当变化回调 | `@StorageLink(...) @Watch('onXxx')` | 前者**不是** ArkUI 生命周期，永远不会被调用（见 7.2） |

### 4.4 新增色值令牌的步骤（**三处必须同步**）

`Theme.ets` 每个可变令牌都有三个落点，漏一处就会出现"切深色/重启后回退"：

1. `static XXX: string = '浅色值'` —— 静态初值（= 浅色套值）
2. `private static applyDarkValues()` —— 深色套值
3. `private static applyLightValues()` —— 切回浅色时的恢复值（漏写 → 关不掉深色）

## 5. 画质三档（性能降级）

| 档位 | 光照层预算 `layerBudget` | 模糊系数 `blurScaled` | 适用 |
|---|---|---|---|
| `CINEMATIC`（默认） | 4 | ×1 | 主流/旗舰机 |
| `BALANCED` | 3（砍左侧菲涅尔） | ×0.7 | 中端机 |
| `LITE` | 0（只剩底色+描边+弱投影） | ×0 | 低端机 / 省电 |

基准模糊半径：`LIVE_BLUR 20`、`LIVE_BLUR_SOFT 12`、`DISC_BLUR 18`。
**所有** `backdropBlur` 都必须经过 `GlassLight.blurScaled(base)`，否则切档不生效。
设置页「玻璃画质」写入 `GlassLight.quality` 并持久化，切换后 `bumpRender()`。

## 7. 数据自动刷新链路（记录 / AI 识别后免手动刷新）

### 7.1 链路

```
用户写入（手动录入 / AI 识别确认 / 删除 / 备份恢复 / 清空）
  → DataSource.addRecord / removeRecord（写入路径内部兜底广播）
  → EcoMoodState.broadcastDataChange()
  → EcoMoodState.bump() → AppStorage('ecoTick') + 1
  → 每个页面 @StorageLink('ecoTick') @Watch('onEcoTick') ecoTick
      → onEcoTick() → onStorageChange('ecoTick')
          → EcoMoodState.refresh()   // 重算碳情绪档位（配色跟着变）
          → load()                   // 重新拉数据（列表/统计/积分刷新）
```

切回「记录」Tab 另有一路兜底：`Index.switchTab` 写 `AppStorage('activeTab')`，
记录页 `@Watch('onActiveTab')` 在本页被选中时重拉一次。

### 7.2 关键教训：`onStorageChange` 不是生命周期

页面里曾经写了 30 多个 `onStorageChange(key: string)`，注释也写着「ecoTick 变化会
调用这里」——但 **ArkUI 没有这个回调**（SDK d.ts 里不存在），框架从未调用过它。
`@StorageLink` 只会把组件标脏重建，**重建时用的还是旧数据**，
表现就是「记录完列表不动，必须手动刷新」。

正确写法只有 `@Watch`：

```ts
// 行内链式：变量变化 → 回调方法（官方支持 @State/@Prop/@Link/@StorageProp/@StorageLink…）
@StorageLink('ecoTick') @Watch('onEcoTick') ecoTick: number = 0

onEcoTick(): void {
  this.onStorageChange('ecoTick')   // 复用页面里已经写好的处理逻辑
}
```

### 7.3 刷新可靠性细则

| 场景 | 处理 |
|---|---|
| 连续快速记两笔 | 每次写入都 bump，@Watch 逐次触发；页面 `load()` 无节流，直接重拉 |
| 首页 load 正在飞时又来了新数据 | Dashboard 用 `loadPending` **折叠**成一次补拉，不丢触发、也不并发覆盖 |
| 页面从未打开过 | 首次 `aboutToAppear` 时自然读到最新数据，无需补刷新 |
| AI 识别确认 | `confirm()` 真正 `DataSource.addRecord`（内部广播）→ pop 回上一页 → 上一页已收到 tick 并刷新 |
| 跨天 / 回前台 | `EntryAbility.onForeground` + `EcoMoodState.refresh()` 重算档位 |

## 8. 性能红线

1. **card 档不挂模糊**：一屏十几张卡 = 十几张离屏纹理。
2. **同一区域不叠两层模糊**（父容器模糊 + 子元素模糊）：肉眼不可辨，开销翻倍。
3. **玻璃面零子层**：光照压进元素自身渐变，避免额外合成层。
4. **视差节流**：`AppStorage` 写入会触发所有订阅者重渲，故 80ms 心跳 + 衰减，不逐帧写。
5. **长列表**：`List + LazyForEach + @Reusable`（`ui/LazyList.ets` 提供 `LazySource`），
   记录/积分流水不再一次性建完。
6. **底部滚动余量放在尾部占位 ListItem**，不要挂在 `List` 自身的 padding 上
   （那是滚动视口，会把内容压得永远进不了胶囊区域）。

## 10. 排查口诀（按顺序）

1. **"玻璃看起来不像玻璃 / 不透明"** → 先查页面根底是否**实色**（`bgSolid`），
   再查玻璃底是否被平涂 `backgroundColor` 盖住了光照，最后查染色层 alpha 是否过大。
2. **"深色下有一块暗角 / 很脏"** → 先算「理论叠色值 vs 实测像素值」：
   实测**均匀**偏暗 = 外投影四边渗出（改 `shadowOf`）；
   实测**右下更深且边界硬** = 渐变停靠点「深→白」直连（改 `over()` 预合成）；
   只有 1px 级暗线 = 描边宽度/圆角暗缝。
3. **"改了没反应"** → 查三处：组件有没有订阅 `themeTick`？页面是不是走了另一条
   色值路径（如 `Shadow.card()` 而非 `GlassLight.shadowOf()`）？预览器是否缓存？
4. **"记完数据不刷新"** → 查页面有没有 `@Watch('onEcoTick')`（只写 `onStorageChange`
   等于没接）；再查写入路径有没有走 `DataSource.addRecord`（内部广播）。
5. **"深色模式没适配"** → 先取像素比对浅/深两套令牌值：
   值**精确等于浅色套值** = 换血没生效（全局问题）；
   值对但该深未深 = 页面级适配缺口。
6. **"元素被撑成整屏"** → 百分比光照层（100%×100%）出现在自适应容器里，改零子层。
7. **"同一页有的玻璃亮有的暗"** → 光源方向不一致，检查是否有人写了反向渐变。
